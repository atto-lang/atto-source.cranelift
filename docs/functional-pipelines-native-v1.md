# Cranelift functional pipelines: pure-int64 native JIT subset

**Status: implemented as a separate strict frontend fallback; exact-head native guest execution has not been verified.** The production Cranelift stage-0 source parser remains first in the normal `run`, `ir` and `check` CLI modes. Only if that parser rejects explicit pipeline/arrow-bearing source does the bounded `functional_pipelines` frontend attempt checked lowering. No interpreted fallback and no guest source-to-Rust substitution takes place.

The new `src/functional_pipelines.rs` parser accepts multiple signed-int64 `fnc` declarations, `: int { return ...; }`, `: int -> expression;`, `-> int { return ...; }`, up to four immutable source-order `val` locals, named statically known function calls, checked arithmetic (`+`, `-`, `*`), forward `|>`, and right-associated reverse `<|`. It rejects malformed or mixed-direction unparenthesized expressions, unsupported types/effects, unsafe constructs, missing callees, arity mismatch, ambiguous local uses, symbol shadowing, recursive call graphs and over-budget expansion. All functions are closed-world and checked before the first CLIF instruction is emitted.

**Important restriction:** Cranelift's existing scalar `Expr` IR has no typed let/call nodes. This compiler therefore admits **only functions in which every parameter and immutable local is used exactly once**, with local uses in declaration order, before statically expanding them into checked arithmetic IR. This protects exact-once evaluation and source order without claiming that general Atto function calls or arbitrary local binding uses are implemented. The original programs use each parameter and local once and satisfy this restriction. Widening this subset must add real local/call lowering, not loosen the check.

Run `cargo test --locked --test functional_pipeline_native` to compile the actual Cranelift CLI and then execute the spec's byte-pinned four `.atto` programs. Expected actual JIT stdout lines: **83, 83, 42, 42**. Each positive must pass `check`, emit real CLIF under `ir`, and execute native code under `run`. Negative tests require errors without CLIF output or guest stdout. The canonical eight fixtures match the Git blob SHAs of atto-spec#121. Existing normal scalar tests remain applicable.

This is an in-process native **JIT** for trusted scalar source, NOT native AOT and not a security boundary. General actors, TenantVM isolation, capability checking, I/O, async, ownership and source-edit hotload remain separate compiler/runtime gates. A passing parser test or zero-step Actions run cannot establish guest execution, and no backend PASS is asserted pending real exact-head CI logs.

Related: atto-spec#121, atto-platform-conformance#105/#112, atto-source.rs#381, atto-source.llvm#54.
